# Staff, comandos personalizados y sorteos
## Activación
La jerarquía viene apagada por defecto. El dueño real puede entrar a /setup > Jerarquía de Staff, elegir tres roles y un canal de avisos, o entrar al panel web > Jerarquía Staff. El rol Admin debe tener Administrador de Discord; Staff/Mod no deben tenerlo ni recibirlo por otros roles. No se modifican permisos de Discord automáticamente. Coloca el rol de Timmy por encima de Staff/Mod. Para auditar requiere Ver registro de auditoría; para sancionar requiere Gestionar roles y Moderar miembros. Usa primero Solo avisos (audit), después prueba en un servidor separado y habilita enforce si procede.
Los comandos internos de moderación para Staff se limitan a timeout/untimeout/purge; Mod añade kick y role (solo roles seguros). Admin con Administrador mantiene los accesos existentes. El dueño conserva el control. El rango mayor configurado prevalece. Los permisos nativos de otros roles y bots siguen siendo responsabilidad del dueño. El monitor detecta entradas recientes de auditoría de Discord con ejecutor identificable; no garantiza detectar todas las acciones, y no sanciona intentos rechazados, usuarios sin rango configurado, bots, al dueño ni a miembros con Administrador. Si está activo enforce, manda un aviso antes de aplicar timeout y retirar Staff/Mod. Ante fallos o evidencia incompleta no ejecuta o informa que la sanción quedó incompleta. No revierte automáticamente acciones ya realizadas.
La whitelist solo evita los avisos y sanciones del monitor para IDs explícitos; no concede permisos, no elimina registros oficiales, ni desactiva el log de los comandos normales. La explicación de Timmy se construye con el rango, acción y registro comprobados, no con una acusación inventada por IA.
## Comandos personalizados
Panel > Comandos personalizados. Crea una respuesta o un timeout, o genera un borrador con IA y guarda manualmente. Ejemplo: >customcmd timeout obliterar 10, luego >obliterar @usuario motivo. Se usa el handler timeout existente con su comprobación de permisos y jerarquía. No hay ejecución de JavaScript arbitrario, ni sanciones iniciadas por la IA. Los comandos personalizados funcionan con prefijo; no se registran como slash individuales. Los comandos administrativos de Timmy no se pueden sobrescribir.
## Sorteos
>gend ID_MENSAJE (o /gend) termina un sorteo. >greroll ID_MENSAJE (o /greroll) reemplaza a todos los ganadores actuales por otros participantes si hay suficientes. El resultado y el historial de rerolls quedan en SQLite del volumen. La edición del mensaje se reintenta con el mismo resultado si falla. Solo administradores/dueño, con acceso al canal del sorteo.
## Diversión
>dado 20, >moneda, >8ball pregunta. Los tres tienen variantes slash.
## Persistencia y pruebas
Los nuevos campos se añaden con valores predeterminados al Store v3 existente, sin borrar configuraciones. No se cambia el adaptador Supabase ni el esquema SQL; sorteos siguen usando el volumen. Ejecutar las pruebas de CI y probar roles y auditoría en un servidor aislado antes de activar sanciones.

También se acepta >end y >reroll como alias de los comandos de sorteo. Los tests incluyen cierre y reroll, revisión del borrador web y comprobación de acceso al editor de jerarquía.
